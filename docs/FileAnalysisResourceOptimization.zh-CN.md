# 文件分析资源优化：实施与验收

分支：`feat/file-analysis-resource-safety`。范围限于导入文件；不改变实时会议的默认引擎。

## 目标与检查点

- G1：准备阶段串行，只暂存 16 kHz / mono / PCM16 音频，不复制完整视频。准备失败不留下半成品；旧任务兼容。
- G2：普通转写仍用 60 秒读取窗口 / 最长 22 秒推理片段；窗口提交后可恢复，配置变化不能混用旧结果。
- G3：内存/温度压力在片段边界暂停；用户可暂停/继续；不宣称可抢占底层不可取消的推理。
- G4：文字先可靠保存，再分析说话人；ASR 在阶段切换释放空闲模型。取消辅助分析不删除已交付文字。
- G5：文件 VBx 有保守准入边界；不自动换成 4 人 Sortformer。复用 PCM16 音频，避免完整 Float32 临时副本。
- G6：完成、失败、取消、清理和重启的文件所有权明确；只清理当前任务拥有的文件。
- G7：增加确定性测试和阶段日志。未在 Mac 跑过的构建、测试和性能门不能标为通过。

## 实施批次

1. 资源策略、标准化/持久化音频、串行准备及清理。
2. 窗口检查点、暂停恢复、模型阶段回收、文字先保存。
3. 说话人准入、PCM16 AudioSampleSource、文件 UI 与本地化。
4. 定向测试、差异审查、取消/恢复/磁盘边界复查。

每批完成后更新本文；以 G1–G7 检查，而不是以代码行数或未经实测的收益百分比判断完成。

## 设计取舍

- 首版恢复粒度为转写窗口；准备过程和说话人阶段可以重跑，不持久化底层模型状态。
- 保留 WAV，暂不引入有损压缩归档、依赖分叉、跨窗口 VBx 身份拼接。
- 长文件不得无条件自动执行全程 VBx。保守阈值是安全发布限制，不是实测出的最大能力。
- 不自动选择 Sortformer；需要另做超过 4 人、长间隔身份一致性和长时内存曲线验证。
- 文件任务快照中不保存 API key 或明文敏感配置；配置签名用于阻止不兼容续跑。

## 验收矩阵（待 macOS 执行）

- 30 分钟、2 小时、8–12 小时；WAV/M4A/MP3/MP4/MOV；本地/远程 ASR。
- 8GB/16GB Mac；2 人、4 人、超过 4 人；静音、轻声、边界连续讲话。
- 暂停/取消发生在准备、窗口中间、窗口提交、说话人分析和历史保存阶段。
- 重启恢复、配置变更、磁盘不足、原文件失效、损坏检查点。
- 记录 process physical footprint、MLX active/cache（如可用）、阶段耗时、临时磁盘峰值、温度和前台响应。
- 必须验证转写缓冲不随时长无界增长、文字不重复/不丢失、无主临时文件被清理、说话人失败不丢文字。

### 已审查并修正的边界

- 已交付历史与任务临时音频分离；取消辅助分析不回滚用户已能查看的文字。
- 归档目录可能是外置卷，不能先在队列卷复制后在 MainActor 跨卷移动。现在先在归档卷后台准备，最终同卷移动；准备过程中更换目录会中止提交。
- ASR 配置签名不存凭据，不依赖接口语言、词典使用次数或时间戳。运行中的文件固定词典快照，不随前台 App 切换改变；部分转写恢复时，有效词典变化仍会拒绝混用。
- 没有已提交窗口时可以修正模型配置重试；转写全部完成后可以在不同的当前 ASR 设置下继续说话人分析，历史仍保留原模型信息。
- 说话人模型在准入检查时固定，避免等待推理许可期间设置变化绕过 VBx 安全检查。
- 连续点击取消不能提前把仍在运行的任务标为终态，防止清理过程删除正在读取的音频。
- 暂停/取消意图在中断恢复时保留；普通处理中断才自动重新排队。
- FluidAudio 的 detached 读取任务通过共享 PCM reader 接收取消；文件模式每秒检查内存/温度/前台录音压力，并使后续读取退出。Sortformer 文件模式在窗口边界检查。最终同步聚类和已提交 kernel 不能保证即时抢占。
- 队列状态落盘失败不回收恢复文件。孤儿清理仅限本队列 UUID 命名、超过一天、无队列记录且无检查点清单的文件；队列清单读失败时不清扫。

### 首版明确的预算

- 录音时长最多 12 小时；不再按原视频 4GB 大小拒绝导入。
- 待处理/准备任务最多 64 个，准备音频队列最多 8 GiB。
- 写入安全余量 2 GiB，并在准备/复制中复查；外置归档卷独立检查。
- VBx：物理内存不超过 8 GiB 的设备最多自动分析 30 分钟，其他设备最多 60 分钟。**这是保守发布限制，不是已证明安全的容量公式。** 超限保留文字和续跑音频，提示延后。
- 文件 ASR 每片段结束时，MLX 可回收缓存超过 256 MiB 才清理；不修改进程全局 allocator 上限。这不是整个 App 的 256 MiB 内存承诺。
- 暂停后由用户继续，首版不自动反复尝试并加载模型。
- 文件页说话人选项在该阶段开始时读取；“继续分析”会将“稍后分析”切换为实际分析。选择“仅转写”可结束可选阶段并回收续跑音频。

SwiftPM 问题参考 `.github/workflows/tests.yml`；脚本接受 `SPM_CACHE_PATH` / `SPM_CLONE_PATH`。

3. 校准 VBx 时长门和缓存清理阈值；若未达标，收紧门限或延后分析，不自动退到 4 人模型。

## 暂不纳入本次实现

有损压缩归档、自动选择 Sortformer、VBx 算法内部背压/矩阵重构、VBx 中间状态断点恢复、固定 CPU 百分比控制，以及未经实测的逐模型内存准入公式。现有时长门和内存压力检查不能替代逐模型真机验收。
